# فارسی و انگلیسی باراد — وضعیت اجرا

فارسی زبان اصلی است. ترجمهٔ انگلیسی برای مسیر `/en/` آماده و آزمایش شده، اما در وضعیت فعلی عمومی نیست. فایل‌های WPML 4.9.7، String Translation 3.5.3، WooCommerce Multilingual 5.5.2.1 و Media Translation 2.7.5 از بستهٔ کارفرما نصب شدند. کارفرما تأیید کرد بسته از فروشندهٔ ثالث تهیه شده است. به علت خطای فایل لایسنس، این چهار افزونه موقتاً غیرفعال‌اند و ۱۰ برگه و ۱۴۱ کالای انگلیسی به حالت پیش‌نویس حفظ شده‌اند تا مدیریت و کاتالوگ فارسی قابل استفاده بمانند.

## پیاده‌سازی

- ۱۰ برگهٔ انگلیسی به برگه‌های فارسی پیوند داده شده‌اند؛ ۷ برگهٔ عمومی باراد شامل خانه، کالاها، درباره، تماس، پیش‌فاکتور و دو نمایندگی در المنتور آماده‌اند. سه برگهٔ پیش‌فرض ووکامرس نیز ترجمهٔ مرتبط دارند.
- ۱۴۱ کالای انگلیسی به ۱۴۱ کالای واقعی فارسی وصل‌اند. سایز، SKU، مشخصات عددی، منابع و برگهٔ فنی مشترک حفظ شده‌اند. هر زبان همان ۸ گروه واقعی افشارنژاد را دارد. برای شهید قندی مدل یا موجودی فرضی ثبت نشده است.
- انتخاب‌گر فارسی/English به ترجمهٔ همان صفحه می‌رود. هدایت اجباری بر اساس IP یا مرورگر فعال نیست.
- متن‌های هدر، فوتر، جست‌وجو، فیلترها، فرم‌ها، کارت کالا و سند با `barad_t()` ترجمه‌پذیر شده‌اند. رشته‌ها در دامنهٔ `Barad Site` در String Translation ثبت شده‌اند؛ مقدار پیش‌فرض انگلیسی در `languages/en-defaults.json` قرار دارد.
- هر ترجمه عنوان، توضیح، canonical، زبان HTML و دادهٔ ساختاریافتهٔ خودش را دارد. WPML تگ‌های متقابل fa/en و x-default را تولید می‌کند. قیمت خالی Offer یا امتیاز ساختگی تولید نمی‌کند. هویت Organization برای هر دو زبان به یک موجودیت باراد اشاره می‌کند.
- صفحهٔ قیمت‌گذاری فقط ۱۴۱ کالای اصلی را نشان می‌دهد. ذخیرهٔ WooCommerce CRUD با API رسمی `wpml_sync_custom_field` قیمت پایه، ویژه و تاریخ تخفیف را همگام می‌کند. تست قیمت پایه/ویژه و بازگردانی به قیمت خالی پاس شده است.
- نسخهٔ محلی همچنان `blog_public=0` است. ایندکس، نقشهٔ سایت عمومی و اتصال Search Console باید هنگام انتقال به دامنهٔ اصلی تنظیم شوند.

## مشکل بستهٔ فروشنده

فایل `sitepress-multilingual-cms/classes/admin-menu/configurations/RTL_License_797dfe4d6624fe61.php` در هر دو ZIP پوشهٔ `orginal version` و `Plugin` عیناً یکسان است (SHA-256: `4224d79be35f7dbb0c286e6a34c7b933e7db0e34954cc2391180a3e70b075a99`). Loader رسمی ionCube 15.5.1 روی PHP 8.3.35 و PHP 8.2.4 آزمایش شد؛ هر دو در بوت مدیریت خطای `file is corrupted` می‌دهند. مسیر کوتاه ASCII استاندارد NTFS نیز همان خطا را دارد. هیچ فایل یا بررسی لایسنس تغییر یا حذف نشده است. PHP 8.2 فقط برای آزمون جداگانه استفاده شد و سرور روی PHP 8.3 باقی است.

برای فعال‌سازی نهایی دو زبان، بستهٔ سالم سازگار با PHP 8.3 از فروشنده یا ZIP اصلی از حساب WPML لازم است. ثبت حساب/دامنهٔ لایسنس و ورود اطلاعات خصوصی انجام نشده است. پس از غیرفعال‌سازی موقت، بوت مدیریت سالم است؛ تنظیمات و ارتباط ترجمه‌ها در پایگاه داده حفظ شده‌اند. قیمت‌های فارسی همچنان خالی و ۱۴۱ کالای اصلی منتشرشده‌اند. تا زمان دریافت بستهٔ سالم، انتخاب‌گر زبان نمایش داده نمی‌شود.

## ادامه پس از دریافت بستهٔ سالم

قبل از جایگزینی فایل‌های افزونه بکاپ جدید بگیرید. بستهٔ جایگزین را با نسخه PHP و افزونه‌های وابسته تطبیق دهید؛ بوت واقعی مدیریت و ورود کاربر باید با WPML فعال تأیید شوند. سپس `vendor-package-recovery.php publish` را از CLI اجرا کنید تا وضعیت انتشار قبلی ۱۵۱ ترجمه بازگردد و قیمت‌های فعلی کالاهای فارسی همگام شوند. این دستور تا پیش از رفع خطای بسته نباید اجرا شود. وضعیت بازیابی در `private-backups/wpml-vendor-pause.json` محفوظ است. آزمایش ویرایش با المنتور و قیمت‌گذاری در پنل با WPML فعال باید پس از جایگزینی تکمیل شود.

## فایل‌های بازیابی و بررسی

بکاپ کامل قبل از نصب: `private-backups/before-wpml/wordpress.sql` و `barad-code.zip`، همراه وضعیت قیمت و موجودی. نگاشت ترجمه‌ها: `english-content-manifest.json`. گزارش‌ها در `qa-wpml/` هستند. گزارش‌های محصولات (۲۸۲ صفحه)، چیدمان دو زبان، فرم‌ها و قیمت مشترک مربوط به آزمون قبل از توقف WPML هستند؛ `recovery-verification.json` وضعیت فعلی پنل و سایت فارسی را ثبت می‌کند. اسکریپت‌های ایجاد ترجمه، seed و import را روی تغییرات بعدی مدیر بدون بکاپ و بررسی دوباره اجرا نکنید.
